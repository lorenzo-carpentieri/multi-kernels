# Phase-Based Frequeny Scaling on Aurora: Build and Run
This file contains the step needed for compiling and running the single-gpu benchmarks on Aurora cluster. The same script can be reused on any other cluster by changnin the pbs-bash script and the frequency according to the target hardware.
## Build
Create a build directory:
```
mkdir build
cd build
```
Run CMake to configure the project (set SYnergy paramters for kernel and device frequency scaling and energy profiling using GEOPOM):
```
cmake -DCMAKE_CXX_COMPILER=icpx \
-DENABLED_SYNERGY=ON \
-DSYCL_IMPL=dpcpp \
-DSYNERGY_GEOPM_SUPPORT=ON \
-DSYNERGY_DEVICE_PROFILING=ON \
-DSYNERGY_HOST_PROFILING=ON \
-DSYNERGY_KERNEL_PROFILING=ON \
-DSYNERGY_SYCL_IMPL=DPC++ \
-DSYNERGY_USE_PROFILING_ENERGY=ON \
-DENABLED_TIME_EVENT_PROFILING=ON \
.. 
```

## Run
### STEP 1 
Run the freq_scaling_profiling.py for executing the application with all available frequencies.
```
 python3 scripts/aurora/run/freq_scaling_profiling.py --app-dir=$(pwd)/build/ --benchmarks aop ace metropolis mnist srad  --log-dir=$(pwd)/data/aurora/logs-profiling/ --pbs-path=$(pwd)/scripts/aurora/bash-pbs/ --config-dir=$(pwd)/config/aurora/none/
```
The output will be stored in the log-dir path.The folder contains the csv file for each app and frequency.

### STEP 2
Run the parse_profiling.py script for generating a CSV for each application. 
The CSV file contains the energy and time info for each frequecy and kernel.
```
python3 scripts/aurora/parse-csv/parse_profiling.py --log-dir=$(pwd)/data/aurora/logs-profiling/ --output-dir=$(pwd)/aurora/profiling-csv/ --benchmarks aop ace metropolis mnist srad
```
The output will be stored in the --output-dir path.
### STEP 3 
Run the extract_opt_freq.py for extracting from CSV file the optimal frequency for each kernel and application.
```
python3 scripts/aurora/parse-csv/extract_opt_freq.py --csv-dir=$(pwd)/data/aurora/profiling-csv/ --output-dir=$(pwd)/data/aurora/opt-freq-csv/ --benchmarks aop ace metropolis mnist srad
```
The script generates a CSV file for each application. The CSV contains the optimal frequency for each kernel and the optimal frequency for the entire application.
### STEP 4
Run the generate_config.py for creating the configuration file for APP, KERNEL and PHASE approach.
```
python3 scripts/aurora/parse-csv/generate_config.py --profiling-csv-dir=$(pwd)/data/aurora/opt-freq-csv/ --out-config-dir=$(pwd)/data/aurora/config/ --benchmarks aop ace metropolis mnist srad
```
This script generates a config folder for each apprach: APP, KERNEL and PHASE. In each folder there are the .conf file for each application. The .conf files will be used for running the application with the three different approraches.
### STEP 5 
Modify the configuration file manually.
### STEP 6
Run the opt_freq_scaling.py script for running the application with the configuration file generated by STEP 5.
```
python3 scripts/aurora/run/opt_freq_scaling.py --app-dir=$(pwd)/build/ --log-dir=$(pwd)/data/aurora/final-logs/ --pbs-path=$(pwd)/scripts/aurora/bash-pbs/ --config-dir=$(pwd)/data/aurora/config/ --benchmarks aop
```
This script generates the final data that will be used for generating the final plots that are also showed in the paper.
### STEP 7
Parse the log file generate by STEP 6 and run script generate_single_gpu_plot.py for printing the figure related to the phase-aware approach.
